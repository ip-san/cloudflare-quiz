# `internal` 判定を docs へ引き上げる — レビュアー向け手順

掃引（`sweep-prompt.md`）を一度通した肢のうち、
**`verifiedBy: "internal"`（設問内の整合性だけで偽と判断した）** ものを再検査する。

## なぜやるか

`internal` は「この誤答は設問の枠組みから明らかに偽なので docs は要らない」という判断だが、
**その判断そのものが間違っていた実例が出ている。**

```
2026-08-28  ag-002[2] の反駁に、私（リード）が false を注入した。
            docs の L14/L26 だけを読んで「安いモデルへのフォールバックは無い」と書いたが、
            同じページの L104 に `Fall back to a cheaper model` が明記されていた。
            別の設問（ag-003）と矛盾したことで、初学者のプレイテスターが発見した。
```

つまり **「Cloudflare にそんな機能は無いはずだ」という直感は当てにならない。**
`internal` の肢には、この直感で偽と決めたものが混ざっている可能性がある。

## 探すもの

担当した肢1つずつについて、**docs を現物で読んで**次を判定する:

- **`H1`** — 誤答の中に、Cloudflare の事実として**正しい記述**が混ざっている
  （「正しいが設問の答えではない」ではなく、**正しいことを誤りとして扱っている**場合）
- **`M2`** — `wrongFeedback` が、誤答の主張を否定しきれていない
- **`ok`** — docs に照らして確かに偽であり、反駁も成立している

### `H1` の境界（外すと全部 `H1` になる）

1. 誤答の文をそのまま読んで、Cloudflare の事実として真か
2. 真なら、`wrongFeedback` がそれを「誤り」として否定していないか
3. **主語や条件を書き換えれば真になる、は `H1` ではない。** 現物の文で判定する

## 裏取り

- ローカルキャッシュ `.claude/tmp/docs/` を grep すること
- **`referenceUrl` が指すページは、引用したい行だけでなく全体を読むこと。**
  上の `ag-002` は、引用した2行だけを読んで隣の節を見落として起きた
- 相互に関連する設問（同じ機能を扱う別 ID）があれば、そちらの本文とも突き合わせる

### キャッシュに「無かった」は成立しにくい

2026-08-28 に測ったところ、**756問の `referenceUrl` はすべて
`.claude/tmp/docs/` にキャッシュされている**（536ページ、欠落0）。

つまり「その設問の出典ページがキャッシュに無いから裏が取れない」は起きない。
裏が取れないなら、それは

- 出典ページには書かれていない話題である（→ 関連する他のページを探す）か
- **その主張は存在しない機能についてのもの**（→ 構造的に docs には載らない）

のどちらかで、**探し方の問題ではない可能性が高い**。
ページ内検索で当たらなかった時点で諦めず、まず前者を疑うこと。

### `verifiedBy` の書き分け

- **`docs`** — Cloudflare docs で確認した。**どのファイルのどの記述かを `rationale` に必ず書く**
- **`standard`** — HTTP/DNS/TLS など **Web 標準そのもの**の事実で、Cloudflare docs には原理的に載らない。
  **標準の名前と該当箇所**（「RFC 7231 §6.4.7」など）を `rationale` に必ず書く。
  Cloudflare 固有の挙動（プラン別上限・既定値・製品の手順）には使えない
- **`internal`** — 上のどちらでも裏が取れなかった場合。
  **`rationale` に「なぜ docs に載り得ないのか」を書くこと。**
  「探したが見つからなかった」は理由になりません。
  例: 「『Workers KV は SQL クエリを実行できる』のような、存在しない機能の主張。
  存在しないものは docs に否定形で書かれない」

## 出力

```json
[
  { "id": "ac-017", "optionIndex": 0,
    "verdict": "H1 | M2 | ok",
    "verifiedBy": "docs | standard | internal",
    "problem": "何が問題か（1〜2文。ok なら空文字）",
    "rationale": "docs のどのファイルのどの記述で判定したか",
    "edits": [{ "field": "option.0", "value": "..." },
              { "field": "wrongFeedback.0", "value": "..." }] }
]
```

### 修正案を出すときの注意

- **誤答の文字数を大きく変えないこと（±15字以内）。**
  コーパス全体で正解の長さ順位を各25%に揃えてある
- 誤答を直したら、**その反駁がまだ成立するか**を確認する
- 誤答から主張を削ったら、**反駁がその主張をまだ否定していないか**を確認する
  （消えた主張を否定し続ける「取り残された反駁」になる）
- 絶対語（`一切` `必ず` `常に`）を**弱めないこと。** 誤答が真になります（`H1`）

### 【必須】担当した**全肢**を1エントリずつ返すこと

問題が無ければ `verdict: "ok"`、`edits` は空配列、`rationale` に判定根拠を1行。
提出後に自分で被覆を確認:

```bash
node scripts/check-audit-coverage.mjs <あなたの入力> <あなたの出力>
```

**1肢でも欠けていれば差し戻します。**

- **`src/data/quizzes.json` を直接編集しないこと。** 並列書き込みで壊れます

## 途中で終わる場合

読み切れないと判断したら、**そこで止めて正直に報告してください。**
読んだ分だけを出力し、何肢まで読んだかを書けば、リードが残りを割り直します。

## 最終メッセージに必ず書くこと

**「何肢中いくつ読んで、docs / standard / internal が何件、H1 / M2 / ok が何件だったか」**

`internal` のまま残した肢があれば、その **ID と理由**も列挙してください。
