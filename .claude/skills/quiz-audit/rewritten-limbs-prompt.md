# 書き換えた誤答を docs で裏取りし直す — レビュアー向け手順

**まず `sweep-prompt.md` を読んでください。** 探すもの（H1〜H5・M2）はそちらと同じです。
この文書は、その掃引を**この対象に対して**行うときの前提だけを述べます。

## この肢は何か

長さバイアスの是正（正解が最長になりやすい問題）のために、
**エージェントが書き換えた誤答**です。書き換え時にトランシェ単位の監査は
通っていますが、**`verifiedBy` が記録されていません。**
つまり「読んだ証拠が台帳に無い」状態です。

## なぜ既存の誤答より危ないか

実測（2026-08-27〜28）:

| 対象 | 検出率 |
|---|---|
| 元から在った誤答（初回掃引 1,712肢） | 0.58% |
| **書き換えた誤答**（トランシェ監査 約540肢） | **5.4%** |
| `internal` 判定を docs に当て直した399肢 | 3.0% |

**欠陥は「書き換えた分」に約10倍集中しています。**
誤答を長くする作業は、もっともらしくするために
**その分野で実際に起きること**を書いてしまうためです（`H1`）。

だからこの556肢は、既存誤答の掃引と同じ気持ちで流さないでください。

## この対象で特に多い型

```
H1  dl-010  誤答の中に「本当のこと」が1文だけ紛れていた
    at-010  「WebSocket接続そのものは維持される」が真だった
M2  誤答を厚くする過程で**独立した2つめの誤り**を継ぎ足し、
    反駁が1つめしか否定していない
```

## 裏取り

- **原則 `docs`。** ローカルキャッシュ `.claude/tmp/docs/` を grep すること
- **756問の `referenceUrl` はすべてキャッシュ済み**（536ページ、欠落0）。
  「ページが無いから裏が取れない」は起きません
- `referenceUrl` のページは、引用したい行だけでなく**全体を読むこと**
- `internal` にする場合は **「なぜ docs に載り得ないのか」** を `rationale` に書くこと。
  「探したが見つからなかった」は理由になりません（機械で弾いています）

## 出力・被覆・禁止事項

`sweep-prompt.md` と同じです。要点だけ再掲:

- **担当した全肢を1エントリずつ**返すこと。問題が無ければ `verdict: "ok"`
- `src/data/quizzes.json` を**直接編集しないこと**（並列書き込みで壊れます）
- 誤答の**文字数を大きく変えないこと（±15字以内）**。長さ順位を各25%に揃えてあります
- 絶対語（`一切` `必ず` `常に`）を**弱めないこと。** 誤答が真になります（`H1`）
- 提出後に `node scripts/check-audit-coverage.mjs <入力> <出力>` で自己確認

## 最終メッセージ

「何肢中いくつ読んで、docs / standard / internal が何件、H1 / M2 / ok が何件だったか」
と、`internal` のまま残した肢の ID と理由を必ず書いてください。
