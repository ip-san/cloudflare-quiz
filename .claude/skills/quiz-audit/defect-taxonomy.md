# 誤答の欠陥カタログ

選択肢（特に誤答）を書き換えたときに実際に生まれた欠陥を、**実例つきで**分類したもの。
すべて 2026-07 〜 2026-08 のこのリポジトリで起きたことで、推測は含まない。

各型に「**機械で拾えるか**」を明記している。拾えない型は人（または独立したレビュアー）が
読むしかなく、そこが監査の本体になる。

---

## 機械で拾える型

### M1. 正解の事実の混入（truth-leak）

誤答に、正解が答えとして挙げている値・名前・手順が書かれている。
誤答を読むだけで正解が確定し、消去法の根拠が壊れる。

```
検出: node scripts/check-truth-leak.mjs <baseline>
実例: ct-016 / ac-015（2026-08-26）、lb-012 の `AAAA`、em-015 の `PhishGuard`、
      cs-014 の `Enterprise`、d1-010 の `batch()`
```

**反転作業では4エージェント全員が独立にこれを踏みかけた。** 誤答を「もっともらしく」
しようとすると、正解が述べている事実を書いてしまう。書く時点で避けること。

誤検知も多い。設問文自体が含む数値（`pl-017` の `500GB`）、
4肢すべてに出る UI 用語（`bi-004` の `Allow` / `Do not allow`）、
同じ語で**逆の主張**をしている場合（`dn-005` の `1件`）は正常。

### M2. 反駁されない主張の追加（unrefuted-addition）

誤答を長くするとき、既存の誤りを詳しくするのではなく**独立した2つめの誤り**を
継ぎ足すと、既存の `wrongFeedback` は1つめしか反駁しない。
反駁されなかった主張だけが誤解として残る。

```
検出: node scripts/check-unrefuted-addition.mjs <baseline>
実例: sl-003[2]（Full(strict) の要件を Full の話にすり替えた）
      em-009[3]（複数リージョン同時指定という別主張を足した）
```

### M3. 取り残された反駁（orphaned-refutation）

誤答の本文を差し替えたのに `wrongFeedback` が古い主張を否定し続けている。
反駁の一文が的外れに費やされ、実際に残っている誤りは反駁されない。

```
検出: node scripts/check-orphaned-refutation.mjs <baseline>
実例: bt-016[2]（robots.txt を反駁し続けていた）
```

### M4. 層をまたいだ数値の取り残し（number-drift）

`question` / `options` / `wrongFeedback` / `explanation` の4層に同じ事実を書くため、
見つけた層だけ直して他を取り残す。**解説のほうが先に読まれる**ので実害が大きい。

```
検出: node scripts/check-number-drift.mjs <baseline>
実例: rt-012（wrongFeedback を 15秒→30秒 に直したが解説が15秒のまま）
```

**この検査は差分しか見ないので、「元からずれていた」ものは射程外。**
2026-08-28 の全数掃引で `as-018` が見つかった:

```
explanation   「…Business 500・API Shieldなしの enterprise **500**」
wrongFeedback 「…Enterprise(API Shieldなし)**3,000**」   ← docs は 3000 で解説が誤り
```

**解説は先に読まれる**ので実害が大きい。同じ設問の中で矛盾しているため、
docs を引かなくても気づけるはずだった。

#### 否定的結果: 「設問内の数値矛盾」は機械では拾えなかった

これを検出する `check-internal-number-conflict.mjs` を書いたが、**破棄した。**

- **誤答には誤った数値が入っているのが正常**なので、選択肢どうしの比較は
  原理的にノイズしか出ない（`ar-011` の Free 50/10/100 は全部意図どおり）
- 権威側の層（解説・反駁）に絞っても、**日本語の文中の数値には
  ラテン文字のラベルが隣接しない**。`as-018` の「保存済みエンドポイント数は3,000です」から
  「Enterprise → 3000」は取り出せない
- 実際、**作られた理由である `as-018` を検出できず**、代わりに47件のノイズを出した

ラベル抽出はこのコーパスでは成立しない。**この型はレビュアーが読むしかない。**

### M5. 選択肢が自分で「これは誤解だ」と名乗る（option-self-labeling）

```
✗ 「`$in` なら配列指定で値以外も除外できると誤解しやすい」
✗ 「/index（ファイル名によらず常にこのURLになると考えた場合）」
✗ 「IncludeはANDのように振る舞い、全条件を満たす必要があると考える」
```

読んだ瞬間に外せるので4択が成立しない。**誤答ではなく、誤答についての解説**を
選択肢の位置に置いてしまっている。

```
検出: node scripts/quiz-lint.mjs quality --dry-run
実例: 2026-08-27 の第1トランシェで 186肢中101肢（54%）
```

原因は手順書の書き方だった（「なぜそう思ってしまうのか」→ 信念について語れ、と読まれた）。
→ 書き手向けの対策は `rewriting-distractors.md` の「1-a」。

### M6. 正解だけが特定の書式を持つ（format-giveaway）

正解だけがバッククォートを含む、正解だけが箇条書き、など。

```
検出: node scripts/quiz-lint.mjs distractor --dry-run
実例: r2-003（長さを直した結果、正解だけがバッククォートを持つ状態になった）
```

### M7. 長さから正解の位置が読める（length cue）

```
検出: node scripts/quiz-lint.mjs distractor --dry-run
      （correct-in-longer-half / longest-option-is-correct / correct-longest-by-margin）
```

**この検査は2度、指標が狭すぎて実態を隠した。**

1. 「正解 vs 誤答の**平均**」で測り、756問中17問しか挙がらず
   「修正不能」と誤って結論した
2. 「正解が**最長**か」だけで測り、84.0% → 28.6% を「目標帯に着地」と報告した。
   実際には**正解が「長い方の半分」に入る割合は 95.5% のまま**動いていなかった

→ **バイアスの検査は単一の閾値ではなく分布そのものを出すこと。**

### M8. 誤答どうしだけが同じ言い回しで終わる（parallel-distractor-tails）

「2つの選択肢が同じことを言っているなら、正解は1つなのでどちらも誤り」は古典的な消去法。

```
検出: node scripts/quiz-lint.mjs quality --dry-run
```

ただし**挙がるものの多くは正常**。値の並列（`ar-012`）、設問の形そのもの（`dq-002`）、
鏡写しの誤答（`cs-003` / `as-016` / `em-014`）はいずれも定石の設計。
実際に直すべきなのは「厚くする過程で**新しく**揃った」場合だけ。

### M9. 鏡写しの2肢 → 正解は「両方」

2つの誤答が「**Aだけ**」「**Bだけ**」と空間を分割し、正解が「**AもBも**」になっている形。
**内容を知らなくても「両方」を選べば当たる。**

```
cs-003  誤答1「`result.status` だけを確認すればよい」
        誤答3「`result.ssl.status` だけを確認すればよい」
        正解 「両方が `active` であり、かつ…」

as-016  誤答0「リクエスト数のみで判定され、時間経過による制限は一切存在しない」
        誤答2「時間経過のみで判定され、リクエスト数による制限は一切存在しない」
        正解 「10リクエスト以内**かつ**10分以内」
```

**絞り込み**（機械）: 正解に `両方|いずれも|ともに|かつ`、
誤答2つ以上に `だけ|のみ` があるものを挙げる。
**判定は手作業。** 2026-08-28 の走査では4問挙がり、**本物は2問**だった
（`sp-005` は軸が違い、`sc-003` は正解が「一方のみ」で逆パターン）。

**直し方**: 片方の誤答を、**軸そのものが違う**誤りに差し替える。
消してはいけないのは「もっともらしさ」で、崩すべきなのは「対称性」。

```
cs-003[3] → 「ホスト名の検証と証明書の発行は同じ検証フローを共有しているため…」
            （docs は separate validation flows）
as-016[2] → 「送信元IPアドレス単位で判定される」（docs は session identifier）
```

鏡写しの2肢は語尾も揃うため、直すと `parallel-distractor-tails`（M8）も一緒に減る。

## 機械で拾えない型 — ここが監査の本体

**2026-08-27 の実測: 機械検査を全て通過した約540肢のうち、約5%（29件）がこれだった。**

### H1. 誤った前提の上に「本当のこと」が乗っている

**この作業で最も多い欠陥。** 誤答を「もっともらしく」厚くしようとすると、書き手は
**その分野で実際に起きること**を書く。設問の主語が違うだけで内容は正しい。

| 設問の主語 | 足された一文が実際に説明していたもの |
|---|---|
| `dq-001` Durable Objects | **Workers KV** の結果整合性 |
| `wf-001` WAF | **Load Balancing** のヘルスチェック / **Cloudflare Images** のリサイズ |
| `wp-001` Workers for Platforms | **Workers Builds** の CI/CD |
| `vp-001` Workers VPC | **Durable Objects** のバインディング経由アクセス |
| `lb-016` Sticky | **None** モードのフェイルオーバー挙動 |
| `d1-010` `prepare().run()` | **`batch()`** のロールバック |
| `bt-012` `verified_bot` | **`cf.bot_management.score`** の値域 |
| `rt-005` TURN | **Simulcast / SFU** の解像度調整 |
| `sl-016` Always Use HTTPS | **Automatic HTTPS Rewrites** の書き換え |
| `ob-011` `writeDataPoint()` | **Workers 全般**の非同期処理（docs が明示的に例外としている） |

`wrongFeedback` は前提（主語の取り違え）を否定するが、**足された一文そのものは
否定されない**。学習者はそこだけ正しい知識として持ち帰る。

`dl-010[1]` は同じ構造の別型で、前提「しきい値を高くするほど誤検知が増える」（誤り）の上に
「だから誤ブロックを減らしたいならしきい値を上げるべき」（真）が乗っていた。

**検算の言い方**:

> 「この誤答は誤りか」ではなく、
> **「足した一文を、設問の主語を伏せて読んでも誤りか」**

「これは誤りか？」と自問すると、書き手は主語を見て「誤り」と答えてしまう。

#### H1 の境界 — これを外すと全ての誤答が H1 になる

**「そのまま読んで真である文」だけが H1。**
「主語を書き換えれば真になる文」は H1 ではない。それは**誤答の定義そのもの**で、
すべての誤答が該当してしまう。

2026-08-28 に監査エージェントが `tn-013[0]` を H1 と判定したが、採らなかった:

```
誤答 「レプリカはラウンドロビンやハッシュベースのルーティングによる
      インテリジェントなトラフィック分散をサポートしており、
      Load Balancer を使わなくても均等な負荷分散が可能である」

監査の主張「Load Balancer の真の挙動をレプリカに貼り替えている」
     → 挙げられた「真の一文」は監査が**主語を書き換えて作った文**で、
       選択肢の中には存在しない。文中の主語は一貫して「レプリカ」であり、
       そのまま読めば偽
```

さらにこの誤答の `wrongFeedback` は
「インテリジェントな分散が必要な場合は Cloudflare Load Balancer を使用します」と
**能力を正しい持ち主へ再帰属している**。これは第1波監査が
`ai-005` / `px-005` / `sc-008` / `wa-001` を `ok` と判定したときの基準と同じ。

判定の順序:
1. 足された文を**そのまま**（主語を含めて）読む → 真なら H1
2. 主語を伏せて読む → 真なら H1 の疑い。ただし `wrongFeedback` が
   その能力を正しい持ち主へ名指しで再帰属していれば `ok`
3. 主語を**書き換えれば**真 → **H1 ではない**（ただの誤答）

### H2. 選択肢が自分自身と矛盾している

```
前提: `put()` が存在せず書き込み自体ができない
帰結: だから値を更新するには既存のキーを削除して作り直す必要がある
      ← 作り直すこと自体が書き込みなので、前提と両立しない
```

矛盾した選択肢は「どちらの意味でも読めてしまう」ため、何を反駁すべきかが定まらない。

```
実例: kv-006[0]、wf-015[0]（レスポンスのフィールドを見るのに
      「レスポンスが返る前に確定する」と続けた）、
      dx-016[0]（「同時実行をサポート」＋「キューに積まれ順番に処理」＝逐次は同時の否定）
```

### H3. 誤答が実は真だった（正解が2つある）

誤答を書き換えようとして docs を確認したら、**その誤答が真だった**というケース。
**書き換え作業の副産物として毎ラウンド出る。**

```
実例: tn-005[3] / as-007[2]（2026-08-26、2エージェントが独立に踏みとどまった）
      as-011[2]（2026-08-27、`OPTIONS` プリフライトの扱い。
                 2026-08-26 に同じ問題を「正解が2つある」として直したとき、1肢を取り残していた）
      wr-016（ドキュメント改定で正解が2つになっていた）
```

**「厚くできなかった」という報告は成果である。** 確信が持てない肢は埋めさせないこと。

#### 見分け方: `wrongFeedback` が誤答を半ば認めていないか

誤答が真だと、反駁は正面から否定できず**譲歩の形**になる。これが一番分かりやすい兆候。

```
wa-010[2] 誤答「訪問者のブラウザで JavaScript を無効化していても、
              待機列管理やクッキー発行には一切影響しない」
          反駁「クッキーが無効化されているとキューイング中はアクセスできません。
              **JavaScript 無効化自体は必須条件ではありませんが**、
              選択肢としては前提条件を正しく説明していません」
```

docs の Prerequisites は **CDN / プロキシ済み DNS または LB / クッキー有効化** の3点のみで、
JavaScript は含まれない。**誤答の主張は真**で、反駁はそれを認めたうえで
「前提条件の説明として不適切」という**別の理由**で誤答扱いしていた。

学習者は真の記述を読んで「誤り」と言われるので、
**逆（JS を無効化すると影響する）を覚えて帰る。**

反駁に「〜ではありませんが」「〜自体は正しいものの」「厳密には〜だが」が出てきたら、
**その誤答は誤答になっていない**。docs に照らして検証可能な誤りに差し替えること。

### H4-b. 反駁が正解と矛盾している

反駁を強く書こうとして、**同じ設問の正解が述べている事実を否定してしまう**。

```
ar-018  正解「課金軸が**リクエスト数**とCPU時間であるため…」
        誤答「実行時間をできるだけ長くして…**リクエスト数を減らす**」
        反駁「…**まとめること自体がコスト最適化にはなりません**」
              ← 正解が「リクエスト数は課金軸」と言っているのに、
                反駁がそれを否定している
```

誤答が誤りである理由は「壁時計時間という課金されない軸を狙っている」ことなのに、
反駁が**巻き込みで正しい部分まで否定**していた。
学習者は正解と反駁のどちらを信じればよいか分からなくなる。

**検算**: 反駁を、同じ設問の**正解と並べて読む**。矛盾していないか。

### H4. 反駁が「裏の取れない主張」になっている

反駁を書き足すとき、docs に書かれていないことを断定してしまう。

```
実例: em-009[3] — 「処理するリージョンは1つを選択する仕組みであり、
      複数の国を同時に指定して分散保管する機能はありません」と書いたが、
      docs は4リージョンの一覧を示すだけで、単一選択とも複数選択可能とも書いていない
```

裏が取れないものは `unclear` として**直さずに残す**こと。
「反駁が足りない」より「誤った事実を注入した」ほうが害が大きい。

## H5. 設問をまたいだ矛盾 — どの監査も構造的に見られない

**同じ事実について、2つの設問が逆のことを言っている。**
監査は1問ずつ読むので、**この型は原理的に射程外**。

2026-08-28 のプレイテストで初学者が発見した:

```
ag-002[2] 反駁「Spend limits は予算超過時に安いモデルへ自動的に切り替える機能ではなく、
               `429` を返してブロックする機能です」
ag-003    解説「予算超過時にブロックする代わりに、安いモデルへフォールバックさせることもできます」
```

docs（ai-gateway/features/spend-limits L100-104）は
**予算超過時の選択肢は2つ**と明記している:

  - **Block requests**（既定）
  - **Fall back to a cheaper model** — Dynamic Route と組み合わせる

**`ag-003` が正しく、`ag-002` の反駁が誤りだった。**

### なぜ起きたか — 私が false を注入した

`ag-002` のその一文は**この日の監査で私が足したもの**。
レビュアーが「反駁が『Spend limits の説明です』と言うことで
モデル自動切り替えを黙認している」と報告し、その根拠として
docs L14/L26（「blocks further requests with a `429` response」）を挙げた。

私は **L14/L26 だけを確認して L104 を見なかった。**
提案が指した箇所だけを見て「裏が取れた」と判断したため、
**ページの他の箇所にある反証を見落とした。**

### 検算

- **修正案の根拠が docs の特定行なら、そのページ全体を読むこと。**
  提案が指した行だけを確認するのは裏取りではない
- **相互リンクされた設問（「この分野をもっと深く」）は一緒に読むこと。**
  学習者はリンクを辿るので、矛盾に必ず出会う

この型を見つけたのは**プレイテスト**だった。
`ag-002` と `ag-003` が相互リンクされており、続けてプレイされたため。
**監査とプレイテストは射程が違う**の3例目
（`ar-016` は書き換え前から存在、`ac-008` は元から2主張、これは設問間）。

## 修正案そのものが新しい欠陥を作る

**4回起きた。** 修正案は書き手の提案と同じ検査群に通してから適用すること。

| 修正した対象 | 修正案が作った欠陥 |
|---|---|
| `ag-018` の長さ | `r2-003` に format-giveaway（M6） |
| `pl-002` の H1 | 正解の「SQLでデータを変換するPipelines」を誤答に持ち込んだ（M1） |
| `d1-010` の H1 | 正解の `batch()` を誤答に持ち込んだ（M1） |
| `ob-007` の H1 | 差し替えた文が今度は真になった（H1 の再発） |
| `wp-001` の H1 | 差し替えた文が **Cloudflare Pages** の説明に読めた（H1 の再発） |
| `vp-001` の H1 | 差し替えた文が **Workers KV** の説明に読めた（H1 の再発） |
| `at-017` の H1 | 差し替えで**短くしすぎ**、正解が2位より57%長い状態と format-giveaway を同時に作った |

H1 の修正案が H1 を再発させる率がとくに高い。
**修正案を書いたら、それ自体に「主語を伏せて読んでも誤りか」をかけること。**

### 修正案は「内容」だけでなく「形」も壊す

`at-017` では、真の記述（`McpAgent`）を消すために誤答を短く書き直した結果:

- 正解119字 vs 2位76字 → **`correct-longest-by-margin`**（文体だけで選べる）
- `McpAgent` を消したことで**正解だけがバッククォートを持つ** → `format-giveaway`

内容の欠陥を直したつもりが、長さと書式の手がかりを作っていた。

**修正を適用したら `node scripts/quiz-lint.mjs distractor --dry-run` まで流すこと。**
`quiz-audit.mjs` はこれを含んでいる。内容の検査だけ見て終わらない。
