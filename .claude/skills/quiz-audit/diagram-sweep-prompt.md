# 図を全数監査する — レビュアー向け手順

**この層は一度も系統的に監査されていません**（2026-08-29 時点）。
誤答・正解・解説はすべて全数監査済みですが、図だけが残っています。

## なぜ危ないか

図は**画面に出ます。** そして学習者は図を先に見ます。
それなのに、これまで図の欠陥は2件とも**別件の作業中に偶然**見つかりました:

```
sp-002  Core Web Vitals の改定で FID が INP に置き換わった設問。
        正解肢と反駁を順に直したのに、**図の比較表に
        「FID(First Input Delay)」が残り続けていた。**
        3回直して3回とも図を見落とした

pg-007  Next.js の推奨アダプタが OpenNext から vinext に変わった設問。
        設問・正解・解説は vinext なのに、**図0が OpenNext でビルドする
        流れを描いていた。**しかも図0は vinext の段落に付いていた
```

どちらも「本文は直したが図が古いまま」です。**図は本文と一緒に更新されません。**

## 入力

`targets[]` の各要素が1枚の図:

- `optionIndex` — 図の番号（`{{diagram:N}}` の N に対応）
- `diagram` — 図の構造体そのもの

問題側: `id` / `question` / `correctText` / `explanation` / `referenceUrl`

## 探すもの

### D1. 図が本文と食い違っている

**最も多い型。** 本文を直したときに図が取り残される。

- 図に、正解・解説がもう述べていない**古い名称・数値・手順**が残っている
- 図が描く流れと、解説が述べる流れの**順序が違う**
- 図のラベルが、その図が付いている段落の話題と**ずれている**
  （`pg-007` は vinext の段落に OpenNext の図が付いていた）
- **列挙に見える図が、docs より項目を落としている**

```
tn-008 図0「サービスタイプの分類」
  左列: http / https, tcp / ssh / rdp, unix / unix+tls
  docs(protocols.md): 同じ群に SMB がある
```

ラベルが「分類」で「一覧」ではなくても、**項目が並んでいる以上、
学習者はそれで全部だと読む。** ただし「など」で明示的に開かれている図は対象外。
設問の論点と無関係な網羅性まで求めなくてよい。迷ったら `ok` にして、
`rationale` に「docs には他に X もあるが、設問の論点から外れるので ok」と書けば十分。

### D2. 図が docs と食い違っている

図の数値・名称・順序を `referenceUrl` の現物と照合すること。
**本文が正しくても図だけ古い**ことがあります。

### D3. 図が答えを明かしている — **見なくてよい（構造的に起こらない）**

2026-08-29 にコーパス全体を走査したところ、`{{diagram:N}}` マーカーは
**876枚すべてが explanation 内**にあり、question / hint / options には1つもない。
図は必ず答え合わせの後に出るので、正解を明示していても先に見られることはない。

この不変条件は `scripts/__tests__/diagram-placement.test.mjs` で固定してある。
**この観点に時間を使わないこと。**

### D4. 図の情報量が設問の論点と釣り合っていない

設問が問うていない数値や項目を図が大量に並べていないか。
2026-08-29 のプレイテストで `ag-018` について
「解説が数字だらけで結局どれを覚えればいいのか」という声が出ています。

## 裏取り

- ローカルキャッシュ `.claude/tmp/docs/` を grep すること
- **`referenceUrl` のページは全体を読むこと。** 引用したい行だけを見て
  隣の節を見落とした実例が複数あります
- **grep は行単位です。** docs は文をマークダウンのリンクや `<GlossaryTooltip>` の
  途中で改行します。**短い語で引いて周辺を目で読むこと。**
  文全体を検索語にすると外れ、外れたときに「記述が無い」と誤って結論します

## 修正案を出すときの注意

- 図の構造は型ごとに決まっています（`comparison` の `columns`、`flow` の `steps` など）。
  **既存の構造を壊さないこと。** 項目の増減より、文言の差し替えを優先してください
- `flow.steps` のテキストは短く。`hierarchy.text` は40字以内
  （`quiz:check` が落ちます）
- 図を消す提案はしないでください。`{{diagram:N}}` のマーカーが死にます

## 出力

```json
[
  { "id": "sp-002", "optionIndex": 0,
    "verdict": "D1 | D2 | D3 | D4 | ok",
    "verifiedBy": "docs | internal",
    "problem": "何が問題か（1〜2文。ok なら空文字）",
    "rationale": "判定の根拠。docs のどのファイルのどの記述か、または本文のどこと食い違うか",
    "edits": [{ "field": "diagram.0", "value": { ...図の構造体まるごと... } }] }
]
```

`edits` の `value` は**図の構造体まるごと**を入れてください（部分パッチではありません）。

### 【必須】担当した**全図**を1エントリずつ返すこと

問題が無ければ `verdict: "ok"`、`edits` は空配列、`rationale` に判定根拠を1行。
**1枚でも欠けていれば差し戻します。**

- **`src/data/quizzes.json` を直接編集しないこと。** 並列書き込みで壊れます

## 途中で終わる場合

読み切れないと判断したら、そこで止めて**何枚まで読んだかを正直に報告**してください。
無理に埋めたり、空で返したりしないこと。

## 最終メッセージに必ず書くこと

**「何枚中いくつ読んで、D1/D2/D3/D4/ok が何件だったか」**
