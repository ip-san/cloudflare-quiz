# ヒント層の掃引

756問すべてにヒントがある。**層として一度も監査していない**（2026-08-30 時点）。
誤答・正解・図・初級解説は全数監査済みなので、ここが残っている中でいちばん太い。

同日の初級36問では、設問レベルの欠陥5件のうち**3件がヒントの欠陥**だった。

## ヒントの仕事は一つだけ

**選択肢を絞り込ませること。** 知識を教えることでも、設問を要約することでもない。
「これを読んだ結果、選択肢が減るか」だけを見る。

## 見つける型（すべて実測で出たもの）

### H-1 どの選択肢にも等しく当てはまる（`hw-010`）

    設問  Cloudflare Workflows はどのようなサービスですか？
    ヒント「途中で失敗しても最初からやり直しにならない」処理の仕組み
    選択肢A CI/CDパイプラインを、失敗しても続きから再実行できる形で管理する
    選択肢B（正解）失敗しても状態を保ったまま確実に完了まで実行する耐久実行エンジン

ヒントがAにもBにも等しく当てはまり、絞り込みに使えない。

**注意: 語の重なりでは判定できない。** 上の例はAとBが**違う語で同じことを言っている**。
必ず意味で判断すること。

### H-2 設問を言い換えただけ（`lb-008`）

    設問  Geo Steeringと他機能の互換性に関する正しい説明はどれですか
    ヒント 地理的な振り分けと、任意の条件を書けるカスタムルールが、
           うまく共存できるかどうかを考えましょう

「共存できるかを考えましょう」は設問の問い直しで、判断材料が無い。

## 3つ潰れたとき、原因がヒントでない場合がある（2026-09-12）

**「ヒントが答えを漏らしている」と「誤答がそもそも成り立っていない」は、症状が同じで原因が違う。**
どちらも3肢が落ちる。直す場所が別なので、必ず切り分けること。

### 切り分けの問い

**ヒントを消した状態で、知識のある人はその3肢を即座に捨てられるか。**

- **捨てられる** → 誤答が作り物で、対抗馬になっていない。**ヒントの欠陥ではない。** 誤答層の問題。
- **捨てられない**（もっともらしい誤答で、ヒントの言い回しだけが潰している） → **ヒントの欠陥。**

### 実例

```
lb-005  誤答0（endpoint単位のみ可）と正解2（Pool単位も可）は本当に競る。
        ヒントの言い回しだけが潰していた            → ヒントの欠陥。直した
lb-015  誤答が User-Agent/Referer/Accept、TCPポート/TLS/DNS、IP上位2オクテット/地理/ランダム。
        Session Affinity を知っていれば全部即座に落ちる → 誤答層の問題。ヒントを直しても再発する
wr-005  正解だけが `npm create cloudflare@latest` で、誤答3つは全部 `wrangler ...`。
        「新規作成のツール」に触れる助言はすべて3肢を巻き込む → 誤答層の問題
```

lb-015 と wr-005 は**誤答の作り直しが要る**。ヒントを変えても、意味のある助言にした瞬間に3肢が落ちる。
**ヒント層で直そうとすると、H-2（設問の言い換え）に逃げるしかなくなる。** それは交換であって修正ではない。

### H-4 正解への導出経路を渡す（`kv-008`、2026-09-12）

    設問  `caches.default` でキャッシュしたレスポンスの有効範囲について正しい説明はどれですか
    ヒント Cache APIを呼び出すWorkerはどこで実行されるか、まず思い出してみましょう
    正解  Cache APIはグローバルに利用可能だが、内容は保存が行われたデータセンターの外には複製されない

**語はひとつも重なっていない。** それでも「Worker は1つのデータセンターで動く」→
「だから保存も局所的」という**推論の道筋が、正解そのものの導出経路**になっている。
残り3肢（アカウント全体／オリジンのみ／全世界に複製）はすべてこの一歩で落ちる。

**H-4 は語の照合では絶対に見つからない。** ヒントから出発して、受験者が辿る推論を1〜2歩進めてみて、
その先に正解が現れるなら H-4 である。

**私はこれを2回見逃した。** 一度は「機構を示して導かせる形で教育的」と評価して採用し、
もう一度は助言役も同じ評価をした。**2人が一致しても、4肢に当て直す代わりにはならない。**

### H-3 一般論だけで、選択肢に接続しない（`kv-001`）

    選択肢が Durable Objects / Cache API / D1 / Workers KV の4つの固有名詞のみ
    ヒント「低頻度更新・高頻度読み取り」というワークロードの特性から考えましょう

特性は述べているが、4つのどれがそれに当たるかを判断する材料が無い。
**固有名詞が並ぶ設問では、名前と性質を結ぶ軸を名指しする必要がある。**

### H-4 正解の位置を外している

ヒントが、正解ではない論点へ注意を向けている。
ただし**誤答を1つ潰すヒントは正常**なので、混同しないこと。

### 潰した数で線を引く（2026-09-09 に決めた）

査読者が「ヒントが答えを渡している」と報告する件が続いたので、**潰した誤答の数**を基準にする。
感想ではなく 4 肢それぞれに当てはめて数えること。

```
1つ潰す   正常。ヒントの仕事
2つ潰す   許容。正解を含む2択が残り、そこから先は知識が要る
3つ潰す   欠陥。正解が一意に決まり、ヒントを開くだけで解ける
```

**ただし「3つ潰す」が欠陥なのは、誤答が正解と同じ主題にある場合に限る**（2026-09-11 に追加）。
「X とは何か」「X の役割は」を問う設問で、誤答 3 つが**別製品・別機能の説明**なら、
ヒントが主題を名指しした時点で 3 つとも落ちるのは避けられない。それは誤答設計の型であって欠陥ではない。
主題に向けないヒントは初学者に何も与えない（sl-011 で実際に無内容なヒントを作ってしまった）。

**2 つを欠陥にしない理由**: 二択の軸を示すヒント（「AなのかBなのか」）は構造上かならず 2 つ潰す。
これを禁じるとヒントは「1つの誤答を名指しで否定する」形しか書けなくなり、初学者の道具として弱くなる。
初学者はヒントに強く依存している（09-07〜09 の初級テスターが繰り返し報告）。

**3 つを欠陥にする理由**: 実例が 3 件出ている。dn-009（リードが 09-08 に書いた。「変更したとき」が
存在を前提にして 1 つ、二択の軸が 2 つ潰した）、gw-005（ヒントが正解の言い換えそのもの）、
em-013（設問文の前置きとヒントが二重に構造を述べる）。いずれも内容を知らずに解ける。

査読者が一般化した数字（15/18、12/19）をそのまま採用しないこと。**まず自分で 3 問を 4 肢に当てて数える。**

### 直すときの目標は「2 つ以下」であって「1 つ」ではない（2026-09-11 の失敗）

修正を依頼するとき、私は基準（3つで欠陥）ではなく「潰す誤答は **1 つまで**」と書いて渡していた。
sl-011 でこれが裏目に出た。この設問は誤答 2 と 3 が正解と**まったく別の話題**（TLS モード互換性、API 権限）なので、
**ヒントが「通知」という軸を名指しした時点で、方向を断定しなくてもこの 2 肢が対象外として潰れる**。
1 つ以下にする方法は「軸を出さないこと」しかなく、担当は
「各選択肢を公式ドキュメントと照合しましょう」という**全肢に等しく当てはまるヒント**を書いてきた。
それは hw-010 の型そのもので、潰す数を下げる代わりにヒントを無内容にしていた。

→ **依頼するときは基準どおり「3 つ潰さないこと」と書く。** 2 つは許容。
   誤答が正解と別の話題である設問では、軸を名指しした時点で 2 つ潰れるのが構造的な下限。
   そこを 1 つに詰めようとすると、ヒントが情報を失う。

  sl-011 の最終形: 「証明書の有効期限が近づいたとき、Cloudflare 側から何が届いて何が届かないのかを
  確認してみましょう。」→ 軸は示すが方向を断定しないので誤答0（リマインダーが届く）は潰れない。合計 2 つ。

「絞り込めているか」が基準であって、「正解を直接指しているか」ではない。

## 報告しないもの

- 難易度が高い、という感想だけのもの（ヒントの欠陥ではない）
- 「もっと親切にできる」という改善案（欠陥ではない）
- 答えを言ってしまっているヒント → これは別の型だが、**見つけたら報告してよい**

## 出し方

```json
{
  "findings": [
    {
      "id": "hw-010",
      "type": "H-1",
      "why": "ヒントの『失敗しても最初からやり直しにならない』が、選択肢0(CI/CDが続きから再実行)と選択肢1(耐久実行)の両方に等しく当てはまる。語は違うが意味が同じ",
      "proposal": "CI/CDのようなビルド作業ではなく、Workers上で動くアプリケーションの処理そのものを対象にしている、と対象で切る"
    }
  ]
}
```

- `quizzes.json` は編集しないこと。提案だけを返す。
- **事実を足さないこと。** ヒントに新しい事実を書くなら docs で裏を取り、
  取れないなら「事実を足さずに絞り込む書き方」を提案する。
  `lb-008` では docs 自体が理由を書いていなかったので、
  理由を創作せず「docs は理由を説明していない制約」と明示する形にした。
- 迷ったら報告する。適合率より再現率を優先する。
